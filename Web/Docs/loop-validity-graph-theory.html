Loops as Graphs

A short visual primer on the handful of graph‑theory ideas behind checking whether a loop is valid. No code yet — just pictures and logic.

1. A graph is just dots and lines

A graph is a bundle of dots with lines joining some of them. That is the whole invention. The dots are called nodes (or vertices), and the lines are called edges.

Nothing else comes with it — no shape, no length, no direction (for now). An edge says only one thing: these two nodes are connected.

Picture a chain necklace: each link is a node, joined to the two links beside it. The whole necklace is a graph. So is a map of towns and the roads between them.

Now swap “towns” for “tiles”. In our game the nodes are tiles, and an edge exists between two tiles that share a side.

Hex grid note Tiles are our nodes. Each tile has a position given by a pair of whole numbers, written (q, r). Two tiles are joined by an edge in our graph exactly when they sit side by side and share a border.

2. Adjacency and degree

Two nodes are adjacent when an edge joins them. On our board that simply means “two tiles that are neighbours”.

The degree of a node is the number of edges that touch it. For us, that is: how many of a tile’s neighbours are currently part of the loop.

Hex grid note Every tile in our grid has six neighbour positions — one across each side. In code these are the six axial directions (Hex.AXIAL_DIRECTIONS), and Hex.Neighbours() returns them for any tile. So a tile’s degree is just “how many of those six are currently marked for the loop”.

Here is the number to hold onto: a contented loop tile has degree exactly two — one neighbour in, one neighbour out. If you remember nothing else from this page, remember two.

3. Walks, paths, and cycles

A walk is a stroll from tile to tile along edges. A path is a walk that never visits the same tile twice. A cycle is a path that ends where it began — it closes up.

4. So what makes a loop valid?

Three things have to line up.

(1) Every loop tile has degree exactly two.

(2) The loop is one connected piece.

(3) It is a single cycle — no tile is used twice.

(A chain with degree‑1 ends is not wrong so much as unfinished — it is still waiting to close.)

5. The short cut

Here is the elegant part. Those three rules collapse into a single, checkable condition:

If every loop tile has exactly two loop‑neighbours, and you can reach every loop tile from every other by stepping through loop tiles, then the loop is guaranteed to be one closed cycle.

Why? If each tile has exactly two neighbours, there are no dead ends and no forks — the only things that can exist are rings (you can only keep going round and round). Adding “everything is reachable from everything else” rules out several separate rings. What is left is exactly one ring.

So you never have to trace the loop to know it is closed. You just count: two, two, two… and check it is all one piece.

6. A sketch of the check

In plain steps, a validity check could run like this:

  1. Collect every tile the player has marked for the loop. Those are the nodes.
  2. For each, count how many of its six neighbours are also marked. That count is its degree.
  3. If any tile has degree 3 or more → there is a fork → invalid.
  4. If any tile has degree 0 or 1 → the loop is unfinished (a dangling end), not solved yet.
  5. Pick any loop tile and spread outward through its marked neighbours, noting every tile you reach. (This is a flood fill.)
  6. If you reached every loop tile, it is all one connected piece.
  7. Every tile degree exactly two and all one piece ⇒ one closed cycle ⇒ solved.
Hex grid note Step 5 is a flood fill — the same idea as Hex.FloodFill: start at a tile, queue its neighbours, then their neighbours, and so on, collecting everything connected.
One last split Which way the loop flows (clockwise or anticlockwise) is a separate question from whether it is closed. Direction only matters for the gear rule, and it only makes sense once the loop is shut.

7. Glossary

Node (vertex)
A dot. Here, a tile.
Edge
A line between two nodes. Here, the adjacency between two neighbouring tiles.
Adjacent
Joined by an edge.
Degree
The number of edges touching a node.
Walk
A stroll along edges from node to node.
Path
A walk that never repeats a node.
Cycle
A closed path — it ends where it began.
Connected
You can reach any node from any other by walking along edges.
Flood fill
Spreading from a start node to every reachable node, layer by layer.
